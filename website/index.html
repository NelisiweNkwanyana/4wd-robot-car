Introduction

This project is a physical robot, not a simulation. It starts from a Robocentrix 4WD kit: chassis, four TT gear motors, an L298N driver, an HC-SR04 on a servo, and three IR line sensors. Everything that decides how the robot behaves is my own firmware.

Before writing code I checked the electrical side: current draw against the L298N's limits, the driver's voltage drop on a 2S pack, timer conflicts between the Servo library and PWM pins, and a pin plan that uses all 18 usable UNO pins without a clash.

The firmware is twelve modules with one rule: only the mode manager may command the motors. Behaviours propose a drive command, a safety filter can veto it, and every mode change ramps to a stop first.

The logic runs against a mocked Arduino core on my laptop: 92 automated checks covering mode changes, faults and failsafes. Physical testing follows a written checklist, and results are published here only once they've been measured.

Operating modes

Four modes, one motor owner

Each mode is selected with a single key from the phone or the USB Serial Monitor. Every change ramps the motors to a stop before the new mode starts.

AutonomousT

Line following

  • Three IR sensors: soft and hard corrections
  • Inner wheel reverses on tight curves
  • Coasts through gaps, then searches
  • Stops with a fault if the line is lost
  • Pauses for objects on the track
AutonomousO

Obstacle avoidance

  • Slows at 40 cm, stops at 20 cm
  • Backs off, scans left and right
  • Turns toward the clearer side
  • Re-checks before driving on
  • Gives up safely when boxed in
ManualM

Bluetooth control

  • F B L R plus four curve keys
  • Speed 0–9, q for full
  • Hold-to-drive; stops after 600 ms of silence
  • Refuses to drive forward into an obstacle
ManualK

Joystick control

  • Proportional throttle and steering
  • Centre calibrated at power-on
  • Dead-zone means stop
  • Unplugged wire detected, motors cut
Always onE

Safety layer

  • Emergency stop from any mode, no ramp
  • Debounced low-battery cut-off
  • Validated sensor readings
  • Faults latch until cleared

Shared architecture

Bluetooth keys and the joystick produce the same left/right wheel command through the same mixing function, then pass the same safety filter. Only the input layer differs, so a wireless handheld controller can be added later without touching the motor code.

Wiring

One battery feeds the motor driver and the Arduino's regulator through a switch and fuse. Every ground is joined. Motor speed runs on Timer0 pins so the servo library can't disturb it.
